# Cursor

**Поверхность:** агент редактора · **Ссылка на файл:** `@src/App.tsx` · **Файл правил:** `AGENTS.md`
**В списке приложения:** «Cursor»

## Главное

Cursor правит файлы проекта сам, поэтому просить у него «полный файл целиком» — просить пересказать
код, который уже лежит в репозитории. Задача называется так: результат, файлы через `@`, ограничения,
приёмка, проверка. Для многофайловой или неясной работы — сначала Plan Mode.

## Что говорит документация (октябрь 2026)

- **Правила.** Проектные правила — файлы `.mdc` в `.cursor/rules`; обычный `.md` в этой папке
  **игнорируется**. Для простого случая Cursor предлагает `AGENTS.md` в корне и в подпапках —
  вложенные инструкции комбинируются, более конкретные важнее
  ([Rules](https://cursor.com/docs/rules)).
- **Ограничения размера.** «Keep rules under 500 lines», разбивать большие правила. Чего избегать:
  «Copying entire style guides», «Documenting every possible command», «Adding instructions for edge
  cases that rarely apply», «Duplicating what's already in your codebase».
- **Ссылки на файлы.** `@` подключает файлы и папки (`@auth.ts`, `@src/components/`). Документация
  советует использовать mention, **когда вы знаете, что релевантно**, иначе пусть Agent сам ищет
  ([Prompting agents](https://cursor.com/docs/agent/prompting)).
- **Ссылка в правиле не подставляет содержимое.** Файл в правиле — указание, где смотреть; если
  что-то обязано быть в контексте всегда, это пишут в правило текстом.
- **Plan vs Agent.** Plan Mode исследует кодовую базу, задаёт уточняющие вопросы и показывает план на
  утверждение до написания кода; рекомендуется для сложных многофайловых и архитектурных задач
  ([Plan Mode](https://cursor.com/docs/agent/plan-mode)).
- **Субагенты.** Отдельный «скептический» проверяющий субагент — проверяет заявленное, запускает
  тесты, ищет граничные случаи и сообщает, что прошло, а что нет
  ([Subagents](https://cursor.com/docs/subagents)).
- **Контекст.** «Including irrelevant files can confuse the agent about what's important»
  ([Best practices for coding with agents](https://cursor.com/blog/agent-best-practices)).
- **Строка о правилах в готовом промпте.** Это приложение добавляет к задаче одну строку:
  `- Договорённости проекта лежат в AGENTS.md — прочитай их (@AGENTS.md) и не противоречь им.`

## Промпт

````markdown
## Задача
Кнопка «Экспорт» в шапке отчёта скачивает CSV со всеми отфильтрованными строками.

## Файлы
- @src/components/ExportButton.tsx — новый компонент
- @src/pages/Report.tsx — подключить кнопку в шапке

## Что не меняется
Фильтры, пагинация и стили таблицы. Роутинг не трогать.

## Приёмка
- Нажатие скачивает report.csv с заголовком и строками текущего фильтра.
- Пустой результат — файл из одного заголовка, без ошибки в консоли.
- npm run typecheck и npm test проходят.

## Проверка
Запусти `npm run typecheck` и `npm test` и покажи команду с результатом. Проверку, которой не было,
назови невыполненной.
````

Английская версия — те же заголовки, ссылки остаются `@src/...`. Cursor не различает язык промпта.

Если задача пересекает больше двух-трёх модулей заранее неизвестной структуры — начните в **Plan
Mode** и только потом переходите к правкам.

## Чего не делать

- не просить содержимое изменённых файлов: правки уже в проекте, нужен список путей;
- не подключать «весь проект»: нерелевантные файлы путают Agent;
- не писать правило в `.cursor/rules/что-то.md` — Cursor его не применит, нужен `.mdc`;
- не превращать правило в стайлгайд на 600 строк: предел — около 500 строк, дальше правило режут.
