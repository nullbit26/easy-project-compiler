# Bolt (bolt.new)

**Поверхность:** конструктор · **Ссылка на файл:** обычный путь (файлы выбираются в интерфейсе) ·
**Файл правил:** `AGENTS.md` (Bolt находит его сам; в его документации имя записано строчными — `agents.md`)
**В списке приложения:** «Bolt»

> **Про регистр имени.** Документация Bolt пишет файл как `agents.md`, это приложение пишет
> `AGENTS.md`. На Windows и macOS это один и тот же файл, а `AGENTS.md` — написание самой конвенции
> ([agents.md](https://agents.md/)) и всех остальных инструментов из списка. На файловой системе,
> различающей регистр (Linux), имя стоит сверить с тем, что реально лежит в проекте.

## Главное

Bolt собирает проект сам, и его гайд по промптам называет главное правило прямо: **одно изменение →
проверить → следующее**. Файлы в промпте не подключаются ссылками: нужный файл выбирают в интерфейсе,
а каталоги можно заблокировать от правок.

## Что говорит документация (октябрь 2026)

- **Одно изменение за раз.** «Make one change, check it, then move to the next»; добавлять компоненты и
  функции по одному; маленькие конкретные промпты; прямо говорить, что должно и что не должно
  измениться ([Prompt effectively](https://support.bolt.new/prompting/prompting-effectively)).
- **Plan Mode вместо Discussion Mode.** Discussion Mode закрыт **3 августа 2026**; вместо него Plan
  Mode — обсуждение проекта и план без изменения кода, с возможностью затем «Implement this plan»
  ([Plan Mode](https://support.bolt.new/prompting/plan-mode), [Release notes](https://support.bolt.new/release-notes)).
  Уточнение из документации: с главной страницы Plan Mode сначала создаёт базовую структуру проекта, а
  потом показывает план.
- **Контекст.** Можно приложить документы (PDF, DOC/DOCX, Markdown, текст), код, конфиги и картинки;
  промпт говорит Bolt, как использовать вложение. Постоянный контекст проекта и файл `agents.md`
  описаны на странице управления контекстом
  ([Attach files](https://support.bolt.new/building/upload-files), [Manage project context](https://support.bolt.new/prompting/manage-context)).
- **Цели в интерфейсе.** Файл или выделенный код можно взять целью промпта, а файлы и каталоги —
  заблокировать, чтобы Bolt их не трогал.
- **Проверка.** Документация советует строить маленькими шагами и проверять каждый; отдельного
  автоматического прогона тестов Plan Mode не обещает
  ([Build and refine one step at a time](https://support.bolt.new/building)).
- **Ограничение объёма.** В разделе про проблемы прямо сказано, что большие многосоставные промпты
  перегружают систему ([Issues](https://support.bolt.new/troubleshooting/issues)).

## Промпт

````markdown
## Изменение
На странице отчёта добавить в шапку кнопку «Экспорт», которая скачивает CSV с текущими строками.

## Границы
Оформление страницы и таблицы не менять. Фильтры и навигацию не трогать. Другие страницы оставить
как есть. Новых библиотек не добавлять.

## Как проверить
Нажать «Экспорт» — скачивается report.csv с заголовком и отфильтрованными строками. При пустой
таблице — файл с одним заголовком и без ошибок.
````

Перед следующим изменением дождитесь, пока это проверено: два наложенных изменения без проверки —
основная причина, по которой потом непонятно, что сломалось.

## Чего не делать

- не отправлять «сделай CRM для клиентов» одним промптом: большие многосоставные промпты перегружают
  Bolt;
- не рассчитывать, что Discussion Mode ещё существует — он закрыт в августе 2026;
- не описывать правки словами «где-то в шапке»: файл выбирается в интерфейсе или называется точно;
- не забывать про блокировку файлов, которые менять нельзя: это единственный надёжный способ их
  защитить;
- не ждать, что Plan Mode сам запустит тесты.
