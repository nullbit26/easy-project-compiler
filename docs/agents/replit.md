# Replit Agent

**Поверхность:** конструктор · **Ссылка на файл:** обычный путь ·
**Файл правил:** `replit.md` (Replit создаёт и читает его сам; `AGENTS.md` в документации Replit не заявлен)
**В списке приложения:** «Replit»

## Главное

Replit Agent собирает и правит проект сам. Их гайд по промптам просит: **один результат, наблюдаемые
критерии успеха и границы** («что пока не строить»), а для больших задач — по одному этапу за раз.

> **Важно для этого приложения.** Файл постоянных инструкций Replit — `replit.md` в корне проекта.
> Приложение пишет `AGENTS.md`, `CLAUDE.md` и `.cursor/rules/project.mdc`; Replit их не читает.
> Поэтому у Replit в профиле агента **нет файла правил**: указывать на файл, которого инструмент не
> откроет, — обманывать промпт. Правила при этом всё равно попадают в задачу: они подставляются в
> готовый промпт тем же блоком проверки правил, что и для остальных агентов.

## Что говорит документация (октябрь 2026)

- **Инкрементально.** «Break large tasks into specific functionalities»; для больших сборок — по
  одному этапу ([Effective prompting](https://docs.replit.com/learn/effective-prompting)).
- **Цикл из пяти шагов.** Опишите **один полезный результат**, задайте **наблюдаемые критерии успеха**,
  обозначьте **границы** («пока не делаем вход и базу»), протестируйте и попросите **одно** точечное
  улучшение ([Build your first app](https://docs.replit.com/build/your-first-app)).
- **Контекст.** Называйте нужные файлы, а не прикладывайте проект целиком; в примерах документации
  есть ссылка на документ с проектированием и приложенный макет
  ([Effective prompting](https://docs.replit.com/learn/effective-prompting)).
- **Файл правил.** Agent сам создаёт и читает корневой `replit.md`; вы можете его править и дописывать
  конвенции проекта ([replit.md](https://docs.replit.com/features/project-setup/replit-dot-md)).
- **Режимы.** **Plan mode** — обсуждение, список задач и подход до изменений кода; **Build** — режим по
  умолчанию, когда Plan выключен; отдельный **Design Canvas** — макеты и уточнение дизайна до
  реализации ([Plan mode](https://docs.replit.com/features/agent/plan-mode), [Project editor](https://docs.replit.com/learn/projects-and-artifacts/project-editor)).
- **Проверка.** App Testing: Agent проходит приложение в реальном браузере, разбирает результат и
  исправляет найденное; запускается, когда это уместно, а не после каждого сообщения
  ([App testing](https://docs.replit.com/features/agent/app-testing)).
- **Правила формулировок.** Гайд предпочитает позитивные инструкции, а границы — как отложенные части
  («вход и база — позже»), а не запреты.

## Промпт

````markdown
## Один результат
На странице отчёта появляется кнопка «Экспорт», которая скачивает CSV с текущими строками.

## Критерии успеха
- Нажатие скачивает report.csv с заголовком и отфильтрованными строками.
- При пустой таблице — файл с одним заголовком, без ошибок в консоли.

## Границы
Пока не трогаем: оформление страницы, фильтры, вход пользователя, базу данных. Другие страницы
оставляем как есть.

## Файлы
Кнопка — рядом с компонентом таблицы отчёта; логика выгрузки — там же, где формируются строки отчёта.
````

Если меняется видимое поведение, после сборки попросите проверку сценария в браузере: у Replit она
встроена и находит то, что не видно в коде.

## Чего не делать

- не ждать, что Replit увидит `AGENTS.md`: его файл — `replit.md`;
- не описывать всю фичу одним промптом: цель — один результат, дальше следующий;
- не перечислять запреты вместо границ: «пока не делаем вход» работает лучше, чем список «нельзя»;
- не прикладывать проект целиком: нужны конкретные файлы;
- не путать Plan mode и Design Canvas: первое про подход и задачи, второе про макет.
