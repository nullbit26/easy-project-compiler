# DeepSeek / Веб-чат

**Поверхность:** чат · **Ссылка на файл:** `Target File: <путь>` · **Файл правил:** —
**В списке приложения:** «DeepSeek / Веб-чат»

## Главное

Это чат без доступа к файловой системе: единственный способ передать контекст — приложить код в самом
сообщении, а единственный способ получить результат — попросить **полный** файл целиком. Такой промпт
отличается от остальных одним разделом: в нём есть «сюда копируем» и требование не сокращать код.

## Что говорит документация (октябрь 2026)

- **Официального руководства по промптам для веб-чата нет.** Публичная документация DeepSeek
  описывает модель, режимы и API, но не формат промпта для кода, не работу с `AGENTS.md` и не
  проект-файлы. Единственная конкретная рекомендация по формату относится к **строгому JSON** в API:
  включить JSON-режим, упомянуть слово `json` и привести пример
  ([JSON Output](https://api-docs.deepseek.com/guides/json_mode/)). К обычному промпту для кода это
  не относится — переносить её не нужно.
- **Режимы и версии.** В V4 документированы режимы **Expert** и **Instant**; в API управление
  «усилием рассуждения»: низкое — для простых задач, высокое — для агентных
  ([DeepSeek V4 release](https://api-docs.deepseek.com/news/news260424/), [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)).
- **Загрузка файлов** в приложении существует, но официальные страницы описывают загрузку изображений
  и извлечение текста, а не код-репозиторий
  ([Introducing DeepSeek App](https://api-docs.deepseek.com/news/news250115/), [Upload File](https://api-docs.deepseek.com/api/create-file/)).
  Практически: если не проверили, что файл прикрепился и прочитан, — вставляйте код текстом.
- Всё остальное — общее место для чатов: разделители (заголовки или XML), полный релевантный файл,
  явные требования и критерии приёмки, запрет сокращать код. Это те же правила, что OpenAI и Google
  дают для своих API, и лучшие из доступных ориентиров, пока нет фирменных.

## Промпт

````markdown
## Задача
Исправить выход из системы по истечении сессии: сейчас после истечения токена страница остаётся
открытой до перезагрузки.

## Контекст
- Проект: панель отчётов, TypeScript + React, Vite.
- Запросы идут через обёртку `apiFetch`, состояние сессии — в сторе.

## Исходный код
Ниже — актуальное содержимое файла. Считать его полным: за его пределами ничего не додумывать.

Target File: src/auth/session.ts
```ts
// полное содержимое файла
```

## Требования
- Вернуть ПОЛНЫЙ новый код файла целиком — без «остальное без изменений» и без пустых тел функций.
- Все импорты, типы и экспорты указать полностью.
- Если для решения не хватает другого файла — сказать об этом, а не выдумывать его содержимое.

## Приёмка
- После истечения токена любой запрос уводит на вход без перезагрузки страницы.

## Формат ответа
1. Короткий обзор изменений.
2. Полный код в блоке `Target File: src/auth/session.ts`.
3. Куда скопировать и как проверить.
````

Если не хватает двух-трёх файлов, приложите их все сразу: в чате каждый следующий круг «а покажи ещё
файл» стоит целого раунда и не улучшает результат сам по себе.

## Чего не делать

- не просить «посмотреть проект»: у веб-чата нет доступа к папке, ответ будет выдуман;
- не просить дифф без полного исходника: в чате нечего применять, и границы правки придётся угадывать;
- не рассчитывать на `AGENTS.md`, инструкции проекта и историю репозитория — этого механизма здесь нет;
- не переносить JSON-режим из API в обычный промпт: это требование формата ответа API, а не совет по
  промпту для кода;
- не присылать «фрагмент в середине функции» без указания границ: чат не знает, что было выше.
