# Как запустить

Нужен Node.js 20 или новее: скачайте с https://nodejs.org и установите со стандартными настройками
(«Далее → Далее → Готово»).

1. Распакуйте папку с проектом, например на рабочий стол.
2. Откройте терминал в этой папке:
   - **Windows:** откройте папку, щёлкните правой кнопкой по пустому месту → «Открыть в терминале».
   - **macOS:** щёлкните правой кнопкой по папке → «Службы» → «Новая вкладка в Терминале».
3. Выполните один раз (это займёт 1–2 минуты):

   ```
   npm install
   ```

4. Запустите приложение:

   ```
   npm run dev
   ```

5. Откройте в браузере **http://localhost:3000**

Остановить приложение: нажмите `Ctrl+C` в том же терминале.
Следующий раз достаточно пунктов 4 и 5 — `npm install` нужен только один раз.

## Про ключи

Ключ не обязателен: без него приложение полностью работает на встроенном локальном движке.
Чтобы подключить настоящую модель, нажмите в приложении внизу слева кнопку **«Ключи API»**,
вставьте свой ключ и нажмите «Проверить» — перезапуск не нужен.

- **NVIDIA NIM** — бесплатный ключ: https://build.nvidia.com/settings/api-keys (начинается с `nvapi-`)
- **Google Gemini** — ключ: https://aistudio.google.com/app/apikey (начинается с `AIza`)

Ответ модели идёт 30–60 секунд, всё это время в правом нижнем углу видно, что приложение работает.

## Что приложение делает с твоей папкой

Подключи папку с проектом — и дальше приложение работает прямо с ней, без переноса промптов
руками:

- **Запускает.** Показывает твою страницу или игру в песочнице так, как она выглядит вне
  приложения: картинки, скрипты и стили подгружаются из самой папки.
- **Проверяет.** Само находит, чем проверяется проект (типы, линтер, тесты, сборка), запускает
  это в папке и показывает ошибки с файлом и строкой. Если что-то упало — может попросить
  модель починить именно это, а потом перепроверить теми же командами.
- **Пишет с твоего согласия.** Модель предлагает текст файлов, ты галочками выбираешь, что
  записать. Любую запись можно вернуть одной кнопкой — копии лежат рядом с приложением, а не
  в твоём проекте.
- **Может писать сама (автокодинг).** Правый клик по карточке задачи в плане → «Автокодинг» —
  и приложение само: получает от модели файлы, записывает их, приводит в порядок, запускает
  проверки и, если что-то упало, отправляет ошибки на повтор (до 4 попыток). Всё видно в живом
  терминале в углу экрана, последнюю запись можно отменить. Кнопка «автокодинг всего плана»
  прогоняет готовые задачи очередью — каждая берётся после вердикта предыдущей, а задача,
  чьи проверки не прошли, останавливает очередь: план позади неё не достраивается на падающей
  записи.
- **Приводит файлы в порядок.** Сразу после записи приложение прогоняет записанные файлы через
  тот форматтер, который уже есть в проекте (Prettier, Biome или Ruff). Ничего не скачивается
  и не устанавливается, чужие файлы не трогаются, а если форматтера нет — запись всё равно
  проходит. В истории видно, чем и сколько файлов приведено в порядок.
- **Взвешивает правку.** После записи видно, сколько байт она добавила, сколько проект весит
  сейчас и сколько весил в прошлый раз, а после сборки — насколько потяжелела сама сборка.
  Если правка сильно увеличила проект, приложение об этом скажет. Когда сравнивать не с чем,
  оно так и напишет — выдумывать проценты оно не будет.
- **Сохраняет версии твоим Git.** Видно, какие файлы изменились и что именно в них поменялось;
  выбранные файлы сохраняются как версия у тебя на компьютере. Отправки в GitHub в приложении
  нет — наружу ничего не уходит.

## Про сохранение версий (Git)

Нужен установленный Git: скачай с https://git-scm.com и поставь со стандартными настройками,
затем перезапусти приложение. Если Git не установлен, панель сохранения версий просто скажет
об этом и ничего не сломает.

В самой папке проект должен быть под Git. Один раз открой терминал в папке проекта и выполни:

```
git init
```

Если при сохранении версии приложение попросит имя и почту, выполни один раз (подставь свои):

```
git config --global user.name "Ваше имя"
git config --global user.email "ваша@почта"
```

## Собрать приложение для тестеров

Тестерам не нужен ни Node.js, ни терминал. Одно окно-приложение (portable .exe) собирается так:

```
npm run build:desktop
```

Готовый файл и инструкция для тестеров окажутся на рабочем столе в папке
**«Приложение-для-тестеров»**. Приложение открывается в своём окне, а не в браузере: всё, что оно
запоминает, лежит в папке `data` рядом с самим .exe, а закрытие окна полностью останавливает работу.

Проверить собранное:

```
npm run test:desktop
```

Проверяется, что окно открывается, что данные лежат рядом с приложением, что отвечает его API и что
запуск новой сборки вытесняет уже открытое окно старой, а не показывает старую версию.

## Выпустить обновление, которое приедет само

Приложение умеет обновлять себя: оно раз в несколько часов спрашивает свою ленту релизов, а если
там есть версия новее — предлагает кнопку «Скачать», а когда её не нажимают, тихо скачивает новую
сборку в фоне. Новая версия встаёт на место старого файла при следующем запуске (или сразу, если
нажать «Перезапустить и обновить»). Данные в папке `data` остаются нетронутыми.

Откуда берётся лента: папка `releases/latest/download` публичного репозитория на GitHub. Ни сервера,
ни аккаунта, ни токена внутри приложения — только публичные файлы релиза.

**Один раз:** создайте публичный репозиторий на GitHub и загрузите туда код. Затем соберите адрес
ленты — он вшивается в приложение при сборке:

```
$env:EPC_GITHUB_REPO="ваш-логин/easy-project-compiler"
npm run build:desktop
```

**Каждый релиз:**

1. Поднимите версию в `package.json` (`1.0.0` → `1.1.0`). Именно номер, а не дата сборки, решает,
   что обновление существует: у друзей стоит `1.0.0`, и `1.1.0` для них — новее.
2. Соберите приложение (`npm run build:desktop`).
3. Опубликуйте: `npm run release` (нужен токен с правом `contents: write` в `GITHUB_TOKEN`/`GH_TOKEN`
   или авторизованный GitHub CLI — `gh auth login`; либо загрузите два файла вручную в релиз, см.
   ниже). В конце он сам открывает ленту `releases/latest/download` и сверяет с тем, что собрал:
   «проверено» значит, что приложение увидит обновление, а ошибка называет адрес и код ответа.

`npm run release` сам считает SHA-256 собранного файла и пишет `version.json` — тот самый манифест,
по которому приложение понимает, что скачивать. Вручную это делать не надо и не стоит: опечатка в
хеше выглядит как «обновление не скачивается» и ничего не объясняет.

То же самое на GitHub Actions: положите тег — сборка и публикация пройдут на сервере GitHub (см.
`.github/workflows/release.yml`), а вам останется только `git tag v1.1.0 && git push --tags`.

Как это проверить, не публикуя ничего: в `package.json` поднимите версию, соберите обе сборки с
`EPC_UPDATE_FEED=http://127.0.0.1:3920` (обычный статический сервер с папкой, где лежат `version.json`
и .exe), запустите старую и посмотрите, как она найдёт новую, скачает её и после перезапуска
покажет новый номер.

## Если что-то не так

- **«npm: команда не найдена»** — не установился Node.js, либо терминал был открыт до установки:
  перезапустите терминал.
- **Порт занят** — запустите на другом порту: `PORT=3100 npm run dev` (на Windows в PowerShell:
  `$env:PORT=3100; npm run dev`), затем откройте http://localhost:3100
