# Easy Project Compiler

**Приложение-тренер для тех, кто делает проекты с ИИ.** Оно превращает идею в план, пишет за вас
промпты для кодинг-агента, проверяет его ответы и аккуратно записывает изменения в вашу папку —
только по вашей команде.

</div>

## Что оно делает

- **Мастер проекта** — из описания идеи собирает бриф, архитектуру и план по этапам.
- **Компилятор промптов** — из задачи и правил проекта собирает готовый промпт для агента
  (Cursor, Claude Code, DeepSeek и другие — под каждого своя подача).
- **Проверка ответа** — разбирает ответ агента, показывает, что сделано и что пропущено, и пишет
  следующий промпт доработки.
- **Тренер ошибок** — читает текст ошибки и объясняет, что делать, без жаргона.
- **Файлы и версии** — читает подключённую папку, пишет в неё только после подтверждения, хранит
  копии перед записью и умеет сохранять версии через Git.
- **Автокодинг** — если хотите, приложение само пишет код: задача из плана уходит провайдеру ИИ,
  ответ записывается в папку, код форматируется, запускаются проверки проекта, а при провале
  ошибки уходят на повтор (до 4 попыток). Несколько готовых задач можно запускать конвейером —
  каждая берётся после вердикта предыдущей. Каждый шаг виден в живом терминале, каждая запись
  имеет кнопку отмены, остановить можно в любой момент.

Приложение никогда не читает `.env` и ключи, не отправляет ваш код никуда, кроме выбранного вами
провайдера ИИ, и работает даже без ключа — на встроенном локальном движке.

## Что нового в 1.4.0

- **Модель видит не только названные файлы.** Перед задачей приложение читает импорты в папке:
  в контекст попадают типы, клиенты и тесты, которые задача не назвала, а список путей ведут
  файлы задачи, а не первые 400 по алфавиту. Один переход по импортам, без эмбеддингов и без
  чтения всего диска; бюджет промпта тот же.
- **Папка одна для всех окон.** Если сервер потерял подключение (перезапуск, обновление, свежая
  папка `data`), открытый проект подключает свою папку сам — во «Файлах», Git, проверках, превью
  и студии, а не только в авто-режиме. А когда папка меняется, окна рядом перечитывают её,
  вместо того чтобы показывать код предыдущего проекта.
- **Компилятор промптов работает в консоли.** Пока модель пишет промпт, вместо спиннера и
  серой строки — тот же терминал, что в пошаговом помощнике: что и куда отправлено, какая
  модель отвечает, и текст, который она пишет прямо сейчас. Оборвать сборку можно квадратом
  «Отменить» в шапке терминала — запрос действительно закрывается, а лог остаётся на месте
  промпта с кнопкой «Повторить».
- **Проверка ответа тоже останавливается.** На шаге 4 у ожидания вердикта та же кнопка и тот
  же исход «Отменено»: вердикт не пишется, ошибки нет, вставленный ответ остаётся в поле.
- **Авто-режим сам находит папку проекта.** Если сервер потерял подключение (долго работал до того,
  как папку подключили, или перезапустился без файла состояния), плашка авто-режима сама
  подключает папку проекта и запускает работу. А если подключена чужая папка — откажется
  писать в неё и скажет почему, вместо тихой записи не туда.
- **Экран без сервера больше не врёт.** Если страница открыта без серверной части (например,
  из голого Vite), приложение говорит об этом в заголовке и в сообщениях об ошибках, а не
  показывает «Server error: Not Found».
- **Инструменты студии — в шапке окна.** Добавить окно, готовые раскладки и сброс теперь стоят
  в верхней панели, на одной строке с названием приложения, а не отдельной полосой под ней:
  в студии одна шапка вместо двух. Кнопки видны всё время, пока открыта студия, и уходят
  вместе с ней, когда вы переключаетесь на другой экран.
- **У ИИ свой знак, а не спиннер.** Пока модель думает, в углу появляется квадрат из кубиков:
  они расходятся по своим радиусам, разворачиваются и меняют цвет с фиолетового на небесный.
  Знак никогда не обводят рамкой или плашкой — он не кнопка, — а карточка рядом называет работу,
  считает секунды и честно говорит, если запрос не получился. На двух экранах, где запрос
  показан своим терминалом, карточки нет: там секунды живут в шапке консоли.
- **Строка обновления — свет по краю.** Вместо плитки с заголовком и абзацем: версия, максимум
  одна иконка и тонкий свет, бегущий по краю строки в цвете состояния. Скачивание идёт в фоне
  и видно по полосе прогресса, а не по тексту.
- **Экран рядом — из заголовка окна.** Плюс переехал в верхнюю панель, подальше от «свернуть /
  развернуть / закрыть», и стал того же размера, что в студии: колонка открывается одним
  нажатием, а на трёх колонках кнопка гаснет, вместо того чтобы исчезнуть.
- **Песочница в узкой колонке.** В панели она больше не сжимается в полоску: рейка «источник
  запуска» прячется за иконку в тулбаре, а запущенный проект занимает всю высоту колонки
  (не меньше 240 px). На широком экране рейка остаётся на месте.
- **Одна кнопка на все экраны — включая мастер проекта.** Главное действие — оттенок индиго
  в тонком кольце, а не заливная плита; сплошная заливка осталась только у удаления. Свечения
  и объёмных теней у кнопок больше нет — это закреплено тестом.
- **Папка — строка, а не баннер.** На экране файлов нет ни заголовка «Файлы проекта на диске»,
  ни зелёной галочки: только путь, число файлов и три действия. Текст про `.env`, ключи
  и копии перед записью теперь живёт в подсказке знака «?» рядом с папкой.
- **Уведомления тише.** Компактная нейтральная строка без галочки и эмодзи; появляется и уходит
  плавно, а не скачком.
- **Файл — на карточку.** Строку из списка файлов можно перетащить мышью на задачу
  в плане: путь попадает в контекст этой задачи, а счётчик файлов в подвале карточки
  открывает весь список — с крестиком у каждого.
- **Меньше рамок.** Карточка в карточке убрана на обзоре проекта, на шаге выбора задачи,
  в компиляторе, в мастере создания и на экране файлов: папка, список, открытый файл,
  генерация, проверки, Git и история — одна поверхность с тонкими чертами, а не рамки в рамке.
  Пустые поля больше не занимают полэкрана: поле ответа короткое, пока пустое, а панель
  результата появляется вместе с промптом.
- **Левая панель складывается.** Шеврон рядом с проектами сжимает её до полосы иконок:
  экраны, проекты по инициалам и обратный путь остаются, а работа получает ширину.
  Состояние запоминается между запусками.
- **Студия показывает результат и проверки сразу.** План слева, справа работающий проект над
  проверками и логом автопилота: чтобы увидеть, что получилось, не нужно переключать экраны.
- **Меньше пояснений на экранах.** Абзацы, которые объясняли уже понятный элемент, убраны;
  сведения о поведении приложения живут в подсказках.
- **Один тон на экране компилятора.** Выбранная задача и режим контекста — прижатые тёмные
  клавиши вместо залитых индиго плиток, счётчики правил — числа с точкой вместо цветных
  плашек, предупреждения и ошибки — линия на полях, а не цветная панель. Индиго остался
  у главного действия, «Начать» теперь подписано словом.

## Скачать

Готовые сборки — в разделе [Releases](../../releases/latest): один портабельный `.exe` для Windows.
Он держит все свои данные в папке `data` рядом с собой и обновляется сам — вручную ничего
скачивать не нужно.

## Запуск из исходников

```bash
npm install
npm run dev          # приложение + API на http://localhost:3000
npm run lint         # проверка типов
npm test             # тесты (vitest + jsdom)
npm run eval         # замер контекста промпта: шесть фикстур, старый отбор против графа импортов
```

## Сборка приложения для тестеров

```bash
npm run build:desktop   # portable .exe + инструкция для тестеров
npm run test:desktop    # проверка собранного: окно, данные, API, подмена старой сборки
```

Готовый файл появляется на рабочем столе в папке «Приложение-для-тестеров». Подробно — в
[КАК-ЗАПУСТИТЬ.md](КАК-ЗАПУСТИТЬ.md).

## Обновления

Сборка спрашивает релизы этого репозитория (`releases/latest/download/version.json`), показывает
значок загрузки рядом с номером версии, а если его не нажать — тихо скачивает новую версию в фоне
и подменяет файл при следующем запуске. Данные в `data` при обновлении не трогаются.

Выпуск новой версии:

1. поднять `version` в `package.json`;
2. поставить тег `v1.0.0` (тем же номером) и запушить его — GitHub Actions соберёт приложение и
   опубликует релиз сам;
3. либо собрать локально и опубликовать вручную: `npm run build:desktop && npm run release`
   (нужен токен с правом `contents: write` в `GITHUB_TOKEN`/`GH_TOKEN` или авторизованный
   [GitHub CLI](https://cli.github.com/)). Публикатор сам проверяет опубликованное: если лента
   `releases/latest/download/version.json` не отвечает тем, что собрано, он падает с адресом и кодом,
   а не пишет «готово».

## Устройство

- `src/` — интерфейс (React + TypeScript + Tailwind), экраны, контексты, утилиты;
- `server.ts`, `server/` — локальный сервер: API, чтение и запись файлов, проверки, провайдеры ИИ;
- `electron/` — desktop-оболочка: своё окно, хранилище рядом с `.exe`, автообновление;
- `tools/` — сборка `.exe`, проверка собранного приложения, снимки экранов, публикация релизов
  и замер контекста (`npm run eval`).

Полное описание архитектуры и решений — в [PROJECT_DOCUMENTATION.md](PROJECT_DOCUMENTATION.md).
