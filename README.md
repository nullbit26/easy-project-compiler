# Easy Project Compiler

**Приложение-тренер для тех, кто делает проекты с ИИ.** Оно превращает идею в план, пишет за вас
промпты для кодинг-агента, проверяет его ответы и аккуратно записывает изменения в вашу папку —
только по вашей команде.

</div>

## Что оно делает

- **Мастер проекта** — из описания идеи собирает бриф, архитектуру и план по этапам.
- **Компилятор промптов** — из задачи и правил проекта собирает готовый промпт для агента
  (Cursor, Claude Code, DeepSeek и другие — под каждого своя подача).
- **Проверка ответа** — разбирает ответ агента, показывает, что сделано и что пропущено, и пишет
  следующий промпт доработки.
- **Тренер ошибок** — читает текст ошибки и объясняет, что делать, без жаргона.
- **Файлы и версии** — читает подключённую папку, пишет в неё только после подтверждения, хранит
  копии перед записью и умеет сохранять версии через Git.

Приложение никогда не читает `.env` и ключи, не отправляет ваш код никуда, кроме выбранного вами
провайдера ИИ, и работает даже без ключа — на встроенном локальном движке.

## Скачать

Готовые сборки — в разделе [Releases](../../releases/latest): один портабельный `.exe` для Windows.
Он держит все свои данные в папке `data` рядом с собой и обновляется сам — вручную ничего
скачивать не нужно.

## Запуск из исходников

```bash
npm install
npm run dev          # приложение + API на http://localhost:3000
npm run lint         # проверка типов
npm test             # тесты (vitest + jsdom)
```

## Сборка приложения для тестеров

```bash
npm run build:desktop   # portable .exe + инструкция для тестеров
npm run test:desktop    # проверка собранного: окно, данные, API, подмена старой сборки
```

Готовый файл появляется на рабочем столе в папке «Приложение-для-тестеров». Подробно — в
[КАК-ЗАПУСТИТЬ.md](КАК-ЗАПУСТИТЬ.md).

## Обновления

Сборка спрашивает релизы этого репозитория (`releases/latest/download/version.json`), предлагает
кнопку «Скачать», а если её не нажать — тихо скачивает новую версию в фоне и подменяет файл при
следующем запуске. Данные в `data` при обновлении не трогаются.

Выпуск новой версии:

1. поднять `version` в `package.json`;
2. поставить тег `v1.0.0` (тем же номером) и запушить его — GitHub Actions соберёт приложение и
   опубликует релиз сам;
3. либо собрать локально и опубликовать вручную: `npm run build:desktop && npm run release`
   (нужен токен с правом `contents: write` в `GITHUB_TOKEN`/`GH_TOKEN` или авторизованный
   [GitHub CLI](https://cli.github.com/)). Публикатор сам проверяет опубликованное: если лента
   `releases/latest/download/version.json` не отвечает тем, что собрано, он падает с адресом и кодом,
   а не пишет «готово».

## Устройство

- `src/` — интерфейс (React + TypeScript + Tailwind), экраны, контексты, утилиты;
- `server.ts`, `server/` — локальный сервер: API, чтение и запись файлов, проверки, провайдеры ИИ;
- `electron/` — desktop-оболочка: своё окно, хранилище рядом с `.exe`, автообновление;
- `tools/` — сборка `.exe`, проверка собранного приложения, снимки экранов, публикация релизов.

Полное описание архитектуры и решений — в [PROJECT_DOCUMENTATION.md](PROJECT_DOCUMENTATION.md).
